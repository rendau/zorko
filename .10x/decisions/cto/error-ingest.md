# CTO — error-ingest

**Вердикт:** строим (решение пользователя). Готовые GlitchTip/Bugsink отклонены: нужен свой
продукт на своём стеке, развиваемый до уровня Sentry.

**Стратегия совместимости:** протокол приёма — Sentry (envelope/store). Это даёт сразу все
официальные SDK (web, Flutter, RN) без своих клиентских библиотек и безболезненный переезд
команд с Sentry: меняется только DSN.

**Технологии шага:** Go + franz-go (Kafka-протокол) + Redpanda; Postgres (pgx/mobone);
ClickHouse (clickhouse-go v2); golang-migrate для обеих баз.

**Цена ошибки:** приём — публичная точка, доступная всем браузерам; её отказ = потеря ошибок
клиентов. Поэтому приём максимально простой (никаких походов в БД на запрос), а вся тяжёлая
работа — за очередью.

**Риски:** производительность при неизвестном объёме → горизонтальное масштабирование копиями
и разделами Redpanda; несовместимость с будущими версиями SDK → тесты на образцах пачек.
