# Security — error-ingest

Отчёт: `reviews/2026-11-04-security-review.md`.

- Модель угроз: публичный приём с открытым ключом (ключ в коде сайта) — спам, переполнение,
  чужие сайты; чувствительные данные пользователей в событиях; админский API без входа.
- Сделано: ключ из кэша без похода в БД, `allowed_origin`, лимит ключа, пределы тела до и после
  распаковки, предел события, вычистка ключей-паролей/токенов/кук и номеров карт (Луна),
  IP только при `sendDefaultPii` (`{{auto}}`), параметризованный SQL.
- Обязательно до выхода наружу: админский API (`HTTP_PORT`/`GRPC_PORT`) не публиковать
  (ни ingress, ни Ruto) до шага 5 — входа нет.
- Открытые риски: нет общего предела памяти приёма; строки исходного кода в стеке не чистятся
  (как и в Sentry).
