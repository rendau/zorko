# ADR-011: Имена функций — разбор сжатого JS и поиск объемлющей функции

**Status:** Accepted
**Date:** 2026-11-04
**Feature:** sourcemaps
**Author:** 10x-Team (Architect + Senior Engineer)

## Context
Карта знает исходную строку и колонку, но не имя функции вокруг: имя, которое карта даёт для позиции
ошибки, — это токен на месте ошибки (`price` в `cart.items.price`), а не функция.

## Decision
- Сжатый JS (есть в архиве из CI и в скачанном с сайта) разбирается парсером `dop251/goja/parser`;
  собираются функции с границами и позицией «имени»: объявление, именованное выражение,
  `const x = () => …`/`x = function…`, свойство объекта, метод и поле класса.
- Для позиции кадра (колонка SDK — UTF-16, переводится в байты строки) берётся самая внутренняя
  функция; позиция её имени переводится картой → `names` → исходное имя; нет в `names` — текст
  идентификатора (имена свойств и методов не сжимаются).
- Результат разбора — в памяти по SHA-1 файла (вместе с картами, тот же LRU).
- Запасные пути: парсер не справился или сжатого JS нет → имя по месту вызова в соседнем кадре
  (кадр ниже по стеку; так делал старый Sentry) → иначе сжатое имя.

## Alternatives Considered
| Alternative | Pros | Cons | Why Not |
|---|---|---|---|
| Только имя по месту вызова | без парсера | у нижнего кадра имени нет, ошибки на колбэках | хуже качество; остаётся запасным |
| Имя из `names` в позиции ошибки | проще всего | неверное (токен, а не функция) | неправильно |
| `tdewolff/parse` | быстрый | в AST нет позиций узлов | не найти границы функций |
| esbuild как библиотека | точный парсер | AST не открыт наружу | нельзя |

## Consequences
### Positive
- Имена как в исходниках, включая стрелочные функции в переменных и методы.
### Negative
- Разбор больших бандлов (мегабайты) — десятки–сотни мс на файл; один раз благодаря кэшу.
### Risks
- Новый синтаксис, который goja не разбирает → запасной путь; проверяется на настоящей сборке Vite
  первой задачей M5.
