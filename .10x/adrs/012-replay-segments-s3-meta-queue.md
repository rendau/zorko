# ADR-012: Сегменты записи — сразу в S3 при приёме, описания — через отдельную тему Redpanda

**Status:** Accepted (ключ S3 уточнён ADR-016)
**Date:** 2026-11-06
**Feature:** replay
**Author:** 10x-Team (Architect + Staff Engineer)

## Context
Сегмент записи — тело до нескольких МБ (первый, со снимком страницы) плюс JSON-описание. Ошибки
идут через Redpanda (ADR-002) пачками в ClickHouse. Сообщение Redpanda по умолчанию — до 1 МБ;
ClickHouse не любит мелкие вставки. Поток записей не должен задерживать обработку ошибок.

## Decision
- Приём кладёт тело сегмента в S3 синхронно (таймаут 5 с), ключ
  `replay/<YYYYMMDD начала записи>/<project_id>/<replay_id>/<segment_id>`, всегда zlib
  (голый JSON сервер сжимает сам).
- Описание (без тела) + размер — сообщением в отдельную тему `zorko.replays`
  (`KAFKA_TOPIC_REPLAYS`, своя группа `<KAFKA_CONSUMER_GROUP>-replay`). Отдельный цикл обработки
  пишет в ClickHouse `replay_segment` пачками.
- S3 не ответил → 503 (SDK повторит до 3 раз). Очередь не ответила → 503.
- Сервис очереди переиспользуется второй копией с другой темой; метрики очереди получают метку
  `topic`.

## Alternatives Considered
| Alternative | Pros | Cons | Why Not |
|---|---|---|---|
| Тело в сообщении Redpanda, в S3 — обработчик | приём не ходит в S3 | сообщения до 10 МБ: настройка брокера, тяжёлые пачки, дублирование данных на диске брокера | брокер не для больших тел |
| Всё сразу в ClickHouse с приёма | одна запись | мелкие вставки, приём зависит от ClickHouse | против ADR-002 |
| Описания в Postgres | транзакции, простые выборки | ~720 строк на запись, уборка руками | ClickHouse с TTL дешевле |
| Общая тема с событиями | одна тема | записи задерживают ошибки, другой формат сообщений | изоляция важнее |

## Consequences
### Positive
- Брокер и ClickHouse получают только маленькие описания; приём ошибок не зависит от записей.
- Уборка S3 — удаление папок дня (сегменты записи лежат в одном дне начала).
### Negative
- Приём записей зависит от S3 напрямую (дольше ответ, 503 при сбое S3).
- Сегмент в S3 без описания возможен (очередь упала после S3) — доживает до уборки.
### Risks
- Медленный S3 тормозит приём → отдельный таймаут 5 с, метрика `replay_store_seconds`.

## Dependencies
ADR-002 (очередь), ADR-009 (S3). Ограничивает: смена ключа S3 потребует переноса.
