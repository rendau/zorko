# ADR-014: Связь «запись ↔ проблема» — отдельная таблица, пишется обработчиком событий для всех ошибок

**Status:** Accepted
**Date:** 2026-11-06
**Feature:** replay
**Author:** 10x-Team (Architect + Staff Engineer)

## Context
Ошибка с записью несёт тег `replayId`. Полные события хранятся выборочно (ADR-003): у ошибки, из-за
которой пришла запись, полного события может не быть, и по `event.tags` запись не найти. В
`replay_event.error_ids` есть номера ошибок, но номер → проблема знает только обработчик событий.

## Decision
- Стадия обработчика событий после склейки: события с тегом `replayId` (32 hex) → строки
  ClickHouse `replay_issue (project_id, issue_id, replay_id, event_id, timestamp)` — для всех
  событий пачки, включая «только посчитанные». Пишется вместе с событиями (тот же повтор при сбое).
- Карточка проблемы берёт записи из `replay_issue` ⋈ `replay_segment` (только записи с сегментом 0).

## Alternatives Considered
| Alternative | Pros | Cons | Why Not |
|---|---|---|---|
| Искать по `event.tags['replayId']` | без новой таблицы | теряются записи несохранённых событий | ADR-003 |
| По `error_ids` записи + `event_stat` | без стадии | `event_stat` — агрегаты без номеров событий | нет данных |
| Связь в Postgres | рядом с проблемами | рост строк, уборка руками | ClickHouse с TTL |

## Consequences
### Positive
- У каждой ошибки с записью есть путь к записи, независимо от выборки событий.
### Negative
- Ещё одна вставка в ClickHouse на пачку.
### Risks
- Тег подделан → связь на чужую запись того же проекта; вреда нет: доступ по проекту.

## Dependencies
ADR-003, ADR-004.
