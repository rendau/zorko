# ADR-009: Приём карт по протоколу sentry-cli, файлы в S3 по содержимому, токены организации

**Status:** Accepted
**Date:** 2026-11-04
**Feature:** sourcemaps
**Author:** 10x-Team (Architect + Staff Engineer + Security)

## Context
Фронтендеры должны пользоваться официальными `@sentry/vite-plugin` / `sentry-cli`. Свежий `sentry-cli`
(3.8.2) грузит карты только «архивами» (artifact bundle): `chunk-upload` → куски → `assemble`.
Токен `sntrys_<base64 JSON с url и org>_<секрет>` разбирается самим `sentry-cli`.

## Decision
- Ручки `/api/0/…` на сервере приёма (`INGEST_PORT`, адрес DSN) — новый транспорт
  `handler/sentryapi`, usecase `upload`. Ручки интерфейса токен CI не принимают.
- Токен организации: в PG только SHA-256; права — заливка и релизы своей организации.
- Куски — `chunk/<sha1>` в S3; сборка в фоне (до 2 на копию), строка `artifact_bundle`
  `assembling` — замок между копиями, «зависшая» > 10 мин перезапускается.
- Файлы архива — по одному в S3 `file/<sha1>` (gzip), учёт в PG `blob`; индексы PG
  `artifact_file(debug_id, type)` и `(bundle_id, url)` — для поиска по метке и по пути.
- Пределы против мусора: архив 1 ГБ, файл 200 МБ, всего 2 ГБ, 20 000 файлов.
- Без `S3_ENDPOINT` функция выключена (no-op), остальной zorko работает.
- Релизы — минимум (версия, проекты, `dateReleased`), коммиты и деплои принимаются без хранения.

## Alternatives Considered
| Alternative | Pros | Cons | Why Not |
|---|---|---|---|
| Хранить архив целиком (zip) | проще сборка | на каждый поиск — распаковка zip | файлы читаются по одному и кэшируются |
| Файлы в PG (`bytea`) | без S3 | гигабайты в PG, бэкапы раздуваются | пользователь выбрал S3 |
| Свой формат заливки | проще сервер | свой CLI, несовместимость с плагином | цель — официальные инструменты |
| Токен проекта | меньше ущерб при утечке | токен на каждый репозиторий | пользователь выбрал токен организации |

## Consequences
### Positive
- Плагин работает «из коробки»; одинаковые файлы разных сборок хранятся один раз.
### Negative
- Новый внешний компонент (S3) в эксплуатации; временный диск под сборку архива.
### Risks
- Неучтённые вызовы плагина → проверка с настоящим плагином (M11) до готовности.
- Утечка токена → удаление действует сразу (проверка по базе без кэша).

## Dependencies
Вход CI не зависит от JWT (ADR-005). Уборка — по `last_used_at` (спека, раздел 8).
